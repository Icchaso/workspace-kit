## 決めたこと
| 論点 | 決定 | 理由 |
|---|---|---|
| 渡す相手 | 最初から講座生・お客様に配る | 講座・受託の付加価値にする |
| 形 | 新規の雛形＋既存ツールへの後付け、の両方を1つのスキルから呼ぶ | 新しく作る人と、もう作ってしまった人の両方に効かせる |
| 画面の型 | 共通の骨格（画面幅で3段階に変形）＋ A 指令室・B 現場・C AI相棒 を全部同梱 | 1つのツールの中でも画面ごとに向く型が違う（デモで実証） |
| テーマ | たくさん選べる（awesome-design-skills の67種＝MIT を日本語対応に変換） | 案件ごとに雰囲気を変えたい |
| 配布の芯 | shadcn registry（`npx shadcn add <URL>`）＋ Claude Code プラグイン | 部品のソースが相手のアプリに直接入り、後から自由に直せる |
| デモ | タスク管理ツール（2026-10-21 追加） | 型・テーマ・PC/スマホの違いを1つの題材で触って分かる |

## 守ること
- 受託・他社案件のコードはコピーしない。作法だけ参考にして書き直す（配布物に他社の著作物を混ぜない）
- 第三者の著作権表示（awesome-design-skills・shadcn＝MIT、フォント＝OFL）を `THIRD_PARTY_NOTICES` にまとめる
- ライセンス・価格・利用規約はいっちゃんが決める。規約は事務ちゃんのたたき台 → 弁護士確認
- 公開前にガード君の一次チェック（秘密の値・顧客名・案件名が混ざっていないか）

## 2026-10-21 追記（下タブの動きは iOS 26 版 Instagram が基準）
いっちゃんの録画（Instagram iOS 26・30fps）を1コマずつ測って数値にした。実装は `apps/starter/src/components/shell/bottom-tab-bar.tsx`、合否は `scripts/check-ui.mjs` が数値で出す。
| 場面 | 決めた動き | 実測（雛形・390px） |
|---|---|---|
| 指が触れた瞬間 | 押したタブが選択表示になり、バー全体が 1.03 倍にふくらむ（0.12秒） | 選択表示 3ms／バー 1.028倍 |
| 指を離した瞬間 | 画面を切り替える。中身はフェードも横すべりもしない（即移動） | 見出しが変わるまで 約43ms（離してから） |
| 選択の丸い板 | バネ 0.18秒・揺れ無しで滑る。速い間だけ横に伸びて（最大1.25倍）少し淡くなる | 止まるまで 176ms／伸び 1.20倍 |
| 押さえたまま横になぞる | 板が指についてきて少し大きくなる（1.1倍）。離したタブへ移る | — |
| 動きを減らす設定 | 板は瞬間移動、ふくらみ・伸び無し | 9ms／1.00倍 |
- 合格の線：選択表示 50ms 以内／板 120〜260ms／伸び 1.12倍以上／離してから画面切り替え 150ms 未満
- 実機（iPhone Safari）での手触りの確認はまだ

## 2026-10-21 追記（段階3：画面の型 A/B/C で決めた作法）
| 決めたこと | 理由 |
|---|---|
| 長押しの操作シートは「指を離したとき」に開く（押している間は物が少し沈んで震えるだけ） | 押したまま開くと、指を離した瞬間にシートが閉じた（自動チェックで発見） |
| 削除・明日に回す・完了は確認を挟まず、お知らせの「取り消す」で戻す。確認ダイアログは元に戻せない操作（見本データに戻す）だけ | 1日に何十回もする操作を止めない |
| 一覧の絞り込みと選んだタスクは URL に入れる（`?f=today&id=3`） | 再読み込み・共有・⌘K からの移動で同じ画面に戻れる |
| マウスは「…」でその場のメニュー、指は長押しか「…」で下からの操作シート | 指でもマウスでも同じ操作に2手以内で届く |
| AI への入力は、PC は Enter で送る（Shift+Enter で改行）、指の端末は送るボタン（Enter は改行） | スマホの Enter で書きかけを誤送信しない |
| 土台の CSS は `@layer base` に入れる | 層の外に置くと Tailwind の `outline-none` などで打ち消せない（⌘K の入力欄に青枠が出た） |
| 日本語は `word-break: auto-phrase`（文節で折り返す） | 「ヒーロ／ー画像」のような切れ方を防ぐ |

## 2026-10-21 追記（段階4：テーマ集と見本サイト）
| 決めたこと | 理由 |
|---|---|
| 仕上げは12種。名前は自前の日本語（スカイ・ネイビー・ラベンダー…）にし、元の名前は出さない | 元テーマの名前に実在の会社・製品名（Claude・Sega・Material など）が入っていて、配布物に他社の名前を看板として使わない |
| ブランド名そのもののテーマ11種は「変換のみ」からも外す | 同上。色だけ欲しい場合は仕上げ12種で足りる |
| 色は OKLCH で計算し、書き出しは HEX | 計算は人の目に近い OKLCH が正確。書き出しを HEX にすると axe（自動のコントラスト検査）がそのまま読める |
| 文字と背景の組み合わせ（本文・薄い文字・主色の上の文字・状態色など）は書き出す前に全部 4.6:1 以上に自動で寄せる | 4.5:1 ちょうどだと丸めで落ちることがある。落ちたテーマは除外する仕組みにしたが、結果は0種 |
| 英字フォントには日本語フォントを組み合わせる（例：IBM Plex Sans → IBM Plex Sans JP、丸い字 → M PLUS Rounded 1c、明朝系 → Noto Serif JP）。飾りの強い英字は見出しだけ | 英字だけ指定すると日本語が端末任せの字になり、テーマの雰囲気が出ない |
| Google Fonts に無い字は近い無料の字に置き換える | 配布先で読み込めない字を指定しない |
| 見本サイトは別アプリにせず雛形の中の `/kit` に置く | 見本と本物がずれない。テーマ一覧も同じ生成物を読む |
| 見本の中身は iframe（ページの中に別のページを埋め込む枠）で本物の画面を `?palette=…&theme=…` 付きで開く。URL で渡したテーマは保存しない | 触った人の設定を見本が書き換えないため |

## 2026-10-21 追記（段階5：配る仕組みとプラグイン）
| 決めたこと | 理由 |
|---|---|
| 骨組み（`components/shell/`）から見本のタスクを切り離し、アプリごとに書くのは `config/nav.ts` と `config/shell.tsx`（名前・追加シート・⌘K の候補・外側の入れ物）だけにした | 骨組みがタスクに直接つながっていると、既存のツールに後から入れられない |
| 部品の置き場所は `components/ui/` ではなく `components/kit/` | 多くのアプリが shadcn の `components/ui/button.tsx` を持っていて、同じ名前で上書きしてしまう（まっさらなアプリで `shadcn init` したときに実際にぶつかった） |
| 配る部品は4つ（css → ui → shell → starter。下の物が上の物を連れてくる）。組み立ては自前の台本（`scripts/build-registry.mjs`）で、雛形のビルドのたびに作り直す | 雛形のソースを正本にして、配る物とずれないようにする。shadcn CLI は入れる側の道具としてだけ使う（4.21.3 に固定） |
| CSS は `workspace-kit.css` の1枚にまとめ、相手の `globals.css` には1行足すだけ | 相手の CSS を書き換える量を最小にする |
| 新規は `shadcn init` を使わず `components.json` を置く | init が別の色の変数とボタンを入れ、Workspace Kit の色と混ざる |
| 版で固定した住所（`/r/v0.1.0/…`）でも出す | 配信元を握った人が相手のコードを書き換えられる形なので、入れた版の中身が後から変わらない道を用意する（ガード君の一次チェック） |
| アプリの既定テーマは `<WorkspaceBoot defaultPalette="sky" />` で決める。使う人が選んだ物はその端末で優先（グラファイトも名前で覚える） | 「最初からスカイ」の頼みに応えられなかった |
| 検査台本は相手のアプリにも当てられる形にした（`ROUTES`・`NO_NAV`・見本の操作は `DEMO=1` のときだけ） | 「スマホで崩れてないか見て」を講座生のアプリでも同じ数値で合否にする |
| プラグインはスキル1つ（`workspace-kit`）＋手順書4つ（新規・後付け・テーマ・数値と作法）＋検査台本の写し | 内部スキル（絵心ちゃん・animate・apple-design）は配り先に無いので、使う数値はすべて手順書に書き写した |

検証：まっさらな Next.js 16.4.2 のアプリを2つ作り、手順書どおりに「新規（雛形一式）」と「後付け（ヘッダーのナビがある2画面のアプリに骨格を入れる）」を行い、どちらもビルド・lint・型・検査台本（新規 48画面＋見本の操作／後付け 24画面）が全部合格。後付けで分かった「初期の CSS の `body { font-family }` と `--font-sans` の上書きを外す」は手順書に足した。

## 2026-10-21 追記（段階6：自社の LINE 管理画面への後付けで実証）
とある不動産の LINE 管理画面（13画面・PC 専用）に、手順書どおり後付けした。作業は TOALU のリポジトリの別ブランチ `workspace-kit-retrofit`（手元のみ・本番には出していない）。
| 決めたこと | 理由 |
|---|---|
| 撮影は本物の管理者パスワードと顧客データを使わず、手元だけのにせ Supabase（架空の利用者1人・架空のリード8件）と試験用のクッキーで行う | パスワードの入力は Claude がしてはいけない操作で、顧客の画面を撮って人に見せない |
| 既存の画面の色は1か所ずつ書き換えず、Tailwind の色の名前（gray・green・red・yellow）の行き先をトークンにつなぐ「色の橋」で直す | gray だけで43ファイル609か所。橋なら CSS の数十行で、テーマも効く |
| 指で触る端末だけ、本文の押せる物 44px・入力欄 16px に CSS で底上げする | 画面は PC 向けの大きさで作られていて、画面ごとに直すと17画面に手が入る。マウスの見た目は変えない |
| ナビが6つ以上なら、スマホの下タブは先頭4つ＋「もっと」（0.2.0 で骨格に追加） | 13項目を下タブに並べられない。後付けで初めて分かった |
| ログイン中の人とログアウトは `useAccount()` で骨格に渡す（0.2.0 で追加） | 元のサイドバーにあったログアウトの置き場が骨格に無かった |
| ダーク表示の用意が無いツールは `forceTheme="light"` で明るさを固定（0.2.0 で追加） | 17画面のダーク対応は画面ごとの作業。半端なダークを見せない |
| 版を固定した住所（`/r/v0.1.0/`）の中身は変えず、追加は 0.2.0 として出す | 固定して入れた人のコードが後から変わらない約束を守る |

結果：変更前は主な4画面だけで検査の不合格が164件（ナビの欠落・12px 未満の文字・コントラスト・押せる大きさ・入力欄）。変更後は13画面×6幅×明暗＝156画面で全項目合格。スマホで「もっと」→ 物件管理へ移動、ログアウト → ログイン画面、を実際に押して確かめた。
