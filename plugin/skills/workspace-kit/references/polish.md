# 動きと手触りを仕上げる

「動きを整えて」「触り心地を良くして」「もっとアプリっぽく」「仕上げて」と頼まれたときの手順。新しく作った直後・後付けの最後にも1回流す。
数値は [rules.md](rules.md) の「動き」と同じ。ここに書くのは「どこを・どの順で・何を基準に」直すか。

完了の定義：下の「合格の条件」を全部満たし、検査台本が全部合格し、スマホ幅と PC 幅と「動きを減らす」設定の3つで実際に操作して確かめた状態。

## 1. 偵察（読むだけ・1回だけ）
| 調べること | どこで | 決まること |
|---|---|---|
| 動きの道具 | `package.json`（`motion`・`framer-motion`・`gsap` など） | 無ければ CSS の transition で作る。新しく入れる前に、本当に要るかを疑う |
| 部品の土台 | `@base-ui/react` か `@radix-ui/*` か | メニューやポップオーバーが「押した物から出る」ための CSS 変数の名前（Base UI は `--transform-origin`、Radix は `--radix-<部品>-content-transform-origin`） |
| 時間と曲線のトークン | `--wk-ease-*`・`--wk-dur-*` | 新しい値を作らず、これを使う |
| どれくらい触られるか | 画面を見て表にする | 1日100回以上（⌘K・一覧の行・下タブ・チェック）／時々（シート・お知らせ・追加）／まれ（初回の案内・締めの手順） |

`.next/` や `dist/` などの書き出し物は検索から外す（フレームワーク自身の値が混ざる）。

## 2. 監査（8つの観点）
画面ごとに次を見て、`ファイル:行` と「何が困るか」を表にする。直すのは表を作り終えてから。
| 観点 | 見ること |
|---|---|
| 目的と頻度 | 動きに理由があるか（どこから来てどこへ行ったかを見せる・状態が変わったと知らせる・押した手応え）。1日100回以上の操作とキーボードの操作には動きを付けない |
| 曲線と時間 | 出る物・消える物は `--wk-ease-out`。`ease-in` は使わない（いちばん見られる瞬間が遅れる）。画面の部品は 300ms 未満（シートだけ 420ms） |
| 起点 | メニュー・ポップオーバーは押した物から広がる。`scale(0)` から出さず、0.95〜0.97 倍＋透明から出す（画面中央の確認ダイアログだけは中央でよい） |
| 割り込み | 連打・途中で逆に戻す操作で、動きが最初からやり直したり飛んだりしないか。何度も起きる動き（お知らせ・切り替え・ドラッグ）は transition かバネにする（keyframes は割り込めない） |
| 性能 | 動かすのは `transform` と `opacity` だけ。`width`・`height`・`top`・`margin` を動かさない。大きな面に `backdrop-filter` を重ねない |
| アクセシビリティ | 「動きを減らす」設定で、移動と拡大縮小は止め、色と透明度の変化は残す（消すのではなく穏やかにする）。マウスを乗せたときの動きは `@media (hover: hover) and (pointer: fine)` の中だけ |
| 統一感 | 落ち着いた業務ツールなので弾まない。同じ種類の物は同じ時間と曲線 |
| 足りない動き | 状態がパッと変わって何が起きたか分からない所（完了した行が消える・数字が変わる・保存された）。1画面で目立つ動きは1〜2か所まで |

## 3. 直す順番
上から順に試し、上で済むなら下へ進まない。
1. 消す（理由の無い動き・頻度の高い操作の動き）
2. 減らす（時間を短く・動く距離を小さく・動かす性質を少なく）
3. 曲線を直す（`ease-in` → `--wk-ease-out`）
4. 起点を直す（押した物から出す・`scale(0)` をやめる）
5. 割り込めるようにする（keyframes → transition かバネ）
6. `transform` と `opacity` だけにする
7. 押す動きと戻る動きの時間を変える（意図して押す側はゆっくり、システムの返事はすばやく）
8. 磨き（並んで出る物に 30〜80ms の時間差・切り替えの一瞬のぼかし）
9. 「動きを減らす」設定とマウスの条件を付ける

## 4. 合格の条件（全部満たすまで完了にしない）
- 1日100回以上の操作とキーボードの操作に動きが付いていない
- `ease-in`・`transition: all`・`scale(0)` が無い
- 画面の部品の動きは 300ms 未満（シートを除く）
- メニューとポップオーバーが押した物から出る
- 連打・逆戻しで動きが飛ばない
- 動いているのは `transform` と `opacity` だけ
- 「動きを減らす」設定で移動が止まり、色の変化は残る
- 落ちた項目が残ったまま2回直しても通らなければ、残った理由を相手に報告して止める（通ったことにしない）

## 5. 実測
1. `pnpm build` と `pnpm lint`
2. 検査台本（SKILL.md の「検査」）。下タブの動きの数値も出る
3. スマホ幅（390px）と PC 幅（1440px）で、直した所を実際に押す。連打・途中で止める・逆に戻すも試す
4. 「動きを減らす」設定（Chrome の DevTools → Rendering → `prefers-reduced-motion: reduce`）でもう一度
5. 直す前と後の画像を並べて見せる。動きは画像では伝わらないので、iPhone の実機でも相手に触ってもらう

## iOS のアプリを作るとき
Web ではなく iPhone のアプリ（SwiftUI）を作るなら、部品集の Swift Pieces（https://swiftpieces.com ）が手触りの見本になる。使う人が自分で入れて、その利用条件（MIT + Commons Clause。部品を単体や部品集として売る・配ることはできない）に従う。Workspace Kit には Swift Pieces のコードも、それを Web に移した物も入っていない。
